# NetBSD/ia64 Boot Documentation

$NetBSD$

## Platform Overview

**Architecture**: Intel Itanium (IA-64, Intel Architecture 64-bit)
**Port Date**: 2006-04-07
**Boot Method**: EFI boot (EFI firmware → bootia64.efi → kernel)
**Firmware**: EFI 1.10 or UEFI 2.x
**MMU Requirements**: Region-based virtual addressing, VHPT (Virtual Hash Page Table), software TLB management

## Hardware Support

- **CPU**: Intel Itanium (original), Itanium 2, Itanium 9xxx series
- **Memory**: 64-bit addressing (51-bit virtual, 50-bit physical typical)
- **Boot Devices**: Hard disk (GPT), CD/DVD (El Torito), network (PXE), USB
- **Firmware**: EFI 1.10+, UEFI 2.x
- **Systems**: HP Integrity servers, SGI Altix, Intel development systems

### Supported Systems

**HP Integrity Servers**:
- rx1600, rx2600, rx4640, rx7640, rx8640
- Integrity BL and RP series blades
- Superdome (high-end)

**SGI Altix Systems**:
- Altix 350, 450, 1000, 3000, 4000 series

**Intel Systems**:
- Tiger2, Tiger4 development platforms

## Boot Process

### Stage 0: EFI Firmware

Itanium systems exclusively use EFI (Extensible Firmware Interface):

1. **Power-On Self Test (POST)** - Hardware initialization
2. **EFI firmware initialization** - Load drivers and protocols
3. **Boot Manager** - Select boot option
4. **Load boot application** - `/EFI/BOOT/BOOTIA64.EFI` from ESP
5. **EFI Boot Services** - Provide disk, network, console I/O
6. **Transfer control** - Execute bootloader

**EFI Boot Menu**:
- Access via ESC or F10 during boot (system-dependent)
- Configure boot order
- Add/remove boot entries
- Manual boot options

### Stage 1: EFI Bootloader (bootia64.efi)

**Location**: `/sys/arch/ia64/stand/ia64/efi/`
**Format**: PE32+ executable (EFI application)
**Purpose**: Interactive boot loader with full filesystem support

#### EFI Application Entry

From `/sys/arch/ia64/stand/ia64/efi/start.S`:

```asm
ENTRY(_start, 2)
    alloc   loc0=ar.pfs,2,3,3,0    ; Allocate stack frame
    mov     loc1=rp                ; Save return pointer
    movl    loc2=@gprel(ImageBase) ; Get image base
    add     loc2=gp,loc2

    mov     out0=loc2
    mov     out1=in1
    br.call.sptk.few rp=_reloc     ; Relocate image

    mov     out0=in0               ; image_handle
    mov     out1=in1               ; system_table
    br.call.sptk.few rp=efi_main   ; Call main
```

**Entry parameters**:
- `in0`: EFI_HANDLE (Image Handle)
- `in1`: EFI_SYSTEM_TABLE* (System Table)

#### Self-Relocation

The bootloader performs self-relocation to handle position-independent code:

**Supported relocations** (from `start.S`):
- `R_IA64_DIR64LSB`: 64-bit absolute address (LSB)
- `R_IA64_DIR64MSB`: 64-bit absolute address (MSB)
- `R_IA64_REL64LSB`: 64-bit relative address (LSB)
- `R_IA64_REL64MSB`: 64-bit relative address (MSB)
- `R_IA64_FPTR64LSB`: Function pointer (LSB)
- `R_IA64_FPTR64MSB`: Function pointer (MSB)
- `R_IA64_IPLTLSB`: PLT entry (LSB)

#### Main Bootloader

From `/sys/arch/ia64/stand/ia64/efi/main.c`:

1. **Console initialization**:
   - Set up EFI console protocols
   - Enable input/output

2. **Find PAL procedure**:
   ```c
   find_pal_proc();  // Locate PAL (Processor Abstraction Layer)
   ```
   - Search SAL (System Abstraction Layer) table
   - Extract PAL entry point for kernel

3. **Device initialization**:
   ```c
   efifs_dev_init();      // EFI filesystem devices
   efinet_init_driver();  // EFI network driver
   ```

4. **Determine boot device**:
   - Check `img->DeviceHandle`
   - Configure disk or network boot

5. **Disable watchdog timer**:
   ```c
   BS->SetWatchdogTimer(0, 0, 0, NULL);
   ```

6. **Interactive command prompt**:
   ```c
   interact();  // Enter command loop (doesn't return)
   ```

#### Boot Commands

The bootloader provides an interactive command interface:

**Available commands**:
- `boot [kernel] [flags]` - Load and boot kernel
- `autoboot [delay]` - Auto-boot after delay
- `ls [path]` - List directory
- `cd [path]` - Change directory
- `set var=value` - Set environment variable
- `unset var` - Unset variable
- `show [var]` - Show variable
- `help [command]` - Show help
- `memmap` - Display memory map
- `quit` - Exit to EFI

**Example**:
```
IA-64 EFI boot, Revision 1.0

Type 'help' for help

OK boot netbsd -s
Loading netbsd...
```

### Stage 2: Kernel

**Entry Point**: Kernel entry defined in ELF
**Format**: ELF64
**Load Address**: Kernel virtual address (region-based)

#### Kernel Loading

From `/sys/arch/ia64/stand/common/boot.c`:

1. **Parse command**:
   - Extract kernel name
   - Parse boot flags

2. **Load kernel file**:
   ```c
   file_loadkernel(kernel_name, argc, argv);
   ```

3. **Autoload modules**:
   ```c
   archsw.arch_autoload();
   ```

4. **Execute kernel**:
   ```c
   file_formats[fp->f_loader]->l_exec(fp);
   ```

#### Bootinfo Passed to Kernel

- **EFI System Table**: Pointer to EFI services
- **Memory map**: EFI memory descriptor array
- **ACPI tables**: Root System Description Pointer (RSDP)
- **SAL table**: System Abstraction Layer information
- **SMBIOS**: System Management BIOS
- **PAL entry**: Processor Abstraction Layer entry point

## MMU Setup

### IA-64 Virtual Memory Architecture

**Page Size**: 4KB, 8KB, 16KB, 64KB, 256KB, 1MB, 4MB, 16MB, 256MB (variable)
**Virtual Address**: 64-bit (regions + offset)
**Physical Address**: 50-bit typical (up to 63-bit physical)
**TLB**: VHPT (Virtual Hash Page Table), software-managed
**Address Spaces**: 8 regions (0-7)

### Region-Based Addressing

IA-64 divides the 64-bit virtual address space into 8 regions:

```
Virtual Address Format:
[63:61] - Region number (3 bits, 0-7)
[60:0]  - Regional offset (61 bits)

Region Layout:
Region 0: 0x0000000000000000 - 0x1FFFFFFFFFFFFFFF  (User)
Region 1: 0x2000000000000000 - 0x3FFFFFFFFFFFFFFF  (User)
Region 2: 0x4000000000000000 - 0x5FFFFFFFFFFFFFFF  (User)
Region 3: 0x6000000000000000 - 0x7FFFFFFFFFFFFFFF  (User)
Region 4: 0x8000000000000000 - 0x9FFFFFFFFFFFFFFF  (User)
Region 5: 0xA000000000000000 - 0xBFFFFFFFFFFFFFFF  (Kernel)
Region 6: 0xC000000000000000 - 0xDFFFFFFFFFFFFFFF  (Kernel)
Region 7: 0xE000000000000000 - 0xFFFFFFFFFFFFFFFF  (Kernel I/O)
```

**Region Usage**:
- **Regions 0-4**: User space (5 regions, 2.5EB each)
- **Region 5**: Kernel text, data, BSS
- **Region 6**: Kernel dynamic allocations
- **Region 7**: Uncached I/O, device mappings

### VHPT (Virtual Hash Page Table)

IA-64 uses VHPT for TLB miss handling:

**VHPT Format**:
```
Short Format VHPT Entry (64 bits):
  Bits 0:    P   (Present)
  Bits 1:    MA  (Memory Attribute)
  Bits 2:    A   (Accessed)
  Bits 3:    D   (Dirty)
  Bits 4:    PL  (Privilege Level)
  Bits 5:    AR  (Access Rights)
  Bits 6-7:  Reserved
  Bits 8-51: PPN (Physical Page Number)
  Bits 52-54: ED (Exception Deferral)
  Bits 55-63: IGN (Ignored)

Long Format VHPT Entry (256 bits):
  Additional fields for complex mappings
```

**VHPT Walker**:
- Hardware TLB miss → VHPT lookup
- If found: Automatically insert into TLB
- If not found: Software TLB miss handler

### Page Table Structure

IA-64 uses a **hash-based page table**:

```
Hash Function:
  hash = ((va >> page_shift) XOR region_id) & vhpt_mask

VHPT Table:
  - Sized as power of 2 (typically 64KB - 1MB)
  - Indexed by hash value
  - Collision chains
```

### TLB Management

**TLB Types**:
- **ITLB**: Instruction TLB (16-128 entries)
- **DTLB**: Data TLB (16-128 entries)
- **VHPT**: Virtual Hash Page Table (hardware walker)

**TLB Operations** (via PAL):
- `PAL_VM_SUMMARY`: Get VM features
- `PAL_VM_PAGE_SIZE`: Supported page sizes
- `ptc.l`: Purge local TLB
- `ptc.g`: Purge global TLB
- `ptc.ga`: Purge global TLB all

### Protection and Caching

**Protection Level (PL)**:
- **PL0**: Kernel mode (most privileged)
- **PL1-PL2**: Unused (reserved)
- **PL3**: User mode (least privileged)

**Access Rights (AR)**:
```
AR bits:
  000 = No access
  001 = Read only
  010 = Read/Write (no execute)
  011 = Read/Write/Execute
  100 = Execute only
  101 = Read/Execute
  110 = Read/Write/Execute (promote)
  111 = Read/Write/Execute
```

**Memory Attributes (MA)**:
```
MA bits:
  000 = Write-back cacheable
  001 = Reserved
  010 = Reserved
  011 = Reserved
  100 = Uncacheable
  101 = Uncacheable exported
  110 = Write-coalescing
  111 = Non-cacheable, memory-type RSE
```

### PAL and SAL

**PAL (Processor Abstraction Layer)**:
- CPU-specific firmware
- Low-level processor operations
- TLB management
- Cache control
- Performance monitoring

**SAL (System Abstraction Layer)**:
- Platform-specific firmware
- Error logging
- Platform management
- RTC access
- PCI configuration

## Memory Map

### EFI Memory Map

EFI provides detailed memory map via `GetMemoryMap()`:

```
EFI Memory Types:
  EfiReservedMemoryType        - Reserved
  EfiLoaderCode                - Bootloader code (reclaimable)
  EfiLoaderData                - Bootloader data (reclaimable)
  EfiBootServicesCode          - EFI firmware code (reclaimable)
  EfiBootServicesData          - EFI firmware data (reclaimable)
  EfiRuntimeServicesCode       - Runtime firmware code (persistent)
  EfiRuntimeServicesData       - Runtime firmware data (persistent)
  EfiConventionalMemory        - Available RAM
  EfiUnusableMemory            - Bad RAM
  EfiACPIReclaimMemory         - ACPI tables (reclaimable)
  EfiACPIMemoryNVS             - ACPI NVS (persistent)
  EfiMemoryMappedIO            - Memory-mapped I/O
  EfiMemoryMappedIOPortSpace   - MMIO port space
  EfiPalCode                   - PAL code (Itanium-specific)
```

### Virtual Address Space

**User Space** (Regions 0-4):
```
0x0000000000000000 - 0x9FFFFFFFFFFFFFFF : User processes
```

**Kernel Space** (Regions 5-7):
```
0xA000000000000000 - 0xBFFFFFFFFFFFFFFF : Kernel text, data, heap
0xC000000000000000 - 0xDFFFFFFFFFFFFFFF : Kernel allocations
0xE000000000000000 - 0xFFFFFFFFFFFFFFFF : Uncached I/O space
```

## Installation

### Creating EFI System Partition (ESP)

```sh
# Create GPT partition table
gpt create wd0

# Add ESP (EFI System Partition)
gpt add -t efi -s 256m wd0

# Format as FAT32
newfs_msdos -F 32 /dev/rwd0a

# Mount ESP
mount -t msdos /dev/wd0a /mnt

# Install bootloader
mkdir -p /mnt/EFI/BOOT
cp /usr/mdec/bootia64.efi /mnt/EFI/BOOT/BOOTIA64.EFI

# Copy kernel (optional, for direct EFI boot)
cp /netbsd /mnt/netbsd

# Unmount
umount /mnt
```

### Installing on Existing System

```sh
# Mount existing ESP
mount -t msdos /dev/wd0a /mnt

# Update bootloader
cp /usr/mdec/bootia64.efi /mnt/EFI/BOOT/BOOTIA64.EFI

# Unmount
umount /mnt
```

### Network Boot Setup

**DHCP Configuration** (`/etc/dhcpd.conf`):

```
host itanium-client {
    hardware ethernet 00:30:6E:12:34:56;
    fixed-address 192.168.1.100;
    filename "bootia64.efi";
    option root-path "/export/ia64root";
}
```

**TFTP Setup**:
```sh
# Copy bootloader to TFTP directory
cp /usr/mdec/bootia64.efi /tftpboot/

# Copy kernel
cp /netbsd /tftpboot/netbsd.ia64
```

## Debugging

### EFI Shell

Access EFI shell from boot menu:

**EFI Shell commands**:
```
fs0:                          # Change to filesystem 0 (ESP)
ls                            # List files
cd EFI\BOOT                   # Change directory
BOOTIA64.EFI                  # Execute bootloader
bcfg boot dump                # Show boot configuration
bcfg boot add 0 fs0:\EFI\BOOT\BOOTIA64.EFI "NetBSD"  # Add boot entry
```

### Serial Console

**Configure EFI for serial**:
1. Access EFI Boot Manager
2. Select "Boot Maintenance Manager"
3. Select "Console Options"
4. Enable serial console

**Serial parameters**: 115200 baud, 8N1 (typical)

### Boot Debugging

**Verbose boot**:
```
OK boot netbsd -v
```

**Drop to debugger**:
```
OK boot netbsd -d
```

**Boot from specific device**:
```
OK set currdev=disk1p1:
OK boot netbsd
```

### Common Boot Issues

**Problem**: "Bootloader not found"
**Solution**: Check ESP has `/EFI/BOOT/BOOTIA64.EFI`

**Problem**: "Cannot find PAL proc"
**Solution**: Firmware missing SAL table, update firmware

**Problem**: "Bad ELF magic"
**Solution**: Kernel not for ia64 architecture

**Problem**: Secure Boot errors
**Solution**: Disable Secure Boot in firmware or sign bootloader

### Memory Map Debugging

```
OK memmap
```

Shows EFI memory map with types, addresses, and attributes.

## Platform-Specific Considerations

### Itanium Generations

**Itanium (Merced)**: First generation
- 800 MHz
- 2-4 MB L3 cache
- Used in early HP servers

**Itanium 2 (McKinley, Madison, Montecito)**: Second generation
- 900 MHz - 1.6 GHz
- 1.5-24 MB L3 cache
- Most common Itanium systems
- Used in HP Integrity, SGI Altix

**Itanium 9xxx (Tukwila, Poulson)**: Third generation
- Up to 2.5 GHz
- 24-32 MB L3 cache
- High-end servers

### Byte Order

**Endianness**: Little-endian (bi-endian capable)
**Alignment**: Natural alignment preferred
**Unaligned access**: Supported but slow

### Instruction Set Features

**EPIC (Explicitly Parallel Instruction Computing)**:
- Instruction bundles (3 instructions per bundle)
- Predication (conditional execution)
- Speculation (advanced loads)
- Register rotation

**Register Architecture**:
- 128 general registers (GR0-GR127)
- 128 floating-point registers (FR0-FR127)
- 64 predicate registers (P0-P63)
- 8 branch registers (BR0-BR7)
- Application registers (AR)

### Cache Hierarchy

**L1 Cache**:
- 16 KB I-cache
- 16 KB D-cache

**L2 Cache**:
- 256 KB unified

**L3 Cache**:
- 1.5 MB - 32 MB (depends on model)

### EFI Differences from x86

**PE32+ format**: EFI binaries are PE (not ELF)
**No BIOS compatibility**: Pure EFI, no legacy support
**GPT required**: No MBR support
**64-bit only**: No 32-bit mode

### SKI Simulator

NetBSD/ia64 supports the SKI (Ski Itanium Simulator):

**Location**: `/sys/arch/ia64/stand/ia64/ski/`

**Usage**:
```sh
ski netbsd
```

Useful for testing without physical hardware.
