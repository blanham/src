# NetBSD/rs6000 Boot Documentation

## Platform Overview

NetBSD/rs6000 is the port of NetBSD to IBM RS/6000 workstations and servers. This is a specialized port for older RS/6000 systems that use the POWER and early PowerPC architectures with IBM's proprietary firmware.

Supported systems include:
- IBM RS/6000 Model 7006
- IBM RS/6000 Model 7012
- IBM RS/6000 Model 7013
- IBM RS/6000 Model 7015
- IBM RS/6000 Model 7016
- Other compatible POWER/PowerPC RS/6000 models

These systems use IBM's native firmware (not OpenFirmware or PReP) with the Initial Program Load Control Block (IPL CB) architecture.

## Boot Method

**Primary Boot Method:** IBM IPL (Initial Program Load)

The RS/6000 boot process uses IBM's proprietary boot architecture:
- IPL ROM firmware
- IPL Control Block (IPLCB) data structure
- Boot Unit Control (BUC) information
- LED diagnostic codes
- Network or disk boot capability

### Boot Sequence

1. **Power-On** → IPL ROM initialization
2. **IPL ROM** → Creates IPLCB structure
3. **IPL ROM** → Searches for bootable device (disk/network)
4. **Boot Loader** → Loads from disk or network
5. **Kernel** → Initializes using IPLCB data

## Boot Loader Implementation

### Primary Bootloader: boot

**Location:** `/sys/arch/rs6000/stand/boot/`

The RS/6000 bootloader:
- Runs under IPL ROM control
- Uses IPLCB for hardware information
- Supports network boot (bootp/tftp)
- Provides LED diagnostic feedback
- Loads ELF kernels

**Key Source Files:**
- `boot/boot.c` - Main bootloader logic
- `boot/inkernel.c` - Kernel loading code
- `common/` - Shared boot code

### Boot Image Format

The bootloader is packaged using `mkbootimage`:

```bash
# Create boot image
mkbootimage boot/boot /tmp/boot.fs

# Create boot image with embedded kernel
mkbootimage -m rs6000 -b boot/boot -k ../compile/YOUR_KERNEL/netbsd /tmp/boot.fs
```

## BAT Register Setup

**Source:** `/sys/arch/rs6000/rs6000/machdep.c:initppc()`

### BAT Configuration

The RS/6000 uses multiple BAT mappings for I/O and memory:

```c
void initppc(u_long startkernel, u_long endkernel, u_int args, void *btinfo)
{
    /* Copy bootinfo */
    memcpy(bootinfo, btinfo, sizeof(bootinfo));

    /* Copy IPLCB data structure */
    r_iplcb = (struct ipl_cb *)iplcbinfo->addr;
    r_ipldir = (struct ipl_directory *)&r_iplcb->dir;
    ekern = round_page(endkernel);
    memcpy((void *)ekern, r_iplcb, r_ipldir->cb_bitmap_size);
    iplcb = (struct ipl_cb *)ekern;

    /* Setup BAT mappings */
    oea_batinit(
        0xF0000000, BAT_BL_256M,   /* I/O region 1 */
        RS6000_BUS_SPACE_MEM, BAT_BL_256M,  /* PCI/MCA memory */
        RS6000_BUS_SPACE_IO,  BAT_BL_256M,  /* PCI/MCA I/O */
        0xbf800000, BAT_BL_8M,     /* Additional I/O */
        0);
}
```

### RS/6000 BAT Layout

```
DBAT0: 0xF0000000 - 256MB  (Primary I/O region)
DBAT1: 0x80000000 - 256MB  (PCI/MCA memory space)
DBAT2: 0xC0000000 - 256MB  (PCI/MCA I/O space)
DBAT3: 0xbf800000 - 8MB    (Additional I/O)
```

These mappings provide access to:
- NVRAM and system registers
- MCA (Micro Channel Architecture) devices
- PCI devices (on newer models)
- Diagnostic LEDs
- Serial ports

### LED BAT Mapping

The RS/6000 has diagnostic LEDs accessible via BAT:

```c
/* In bootloader: */
#define BAT_BL_1M   0x0000001c
#define BAT_I       0x00000020
#define BAT_G       0x00000008
#define BAT_PP_RW   0x00000002
#define BAT_Vs      0x00000002

batl = BATL(0xFF600000, BAT_I|BAT_G, BAT_PP_RW);
batu = BATU(0xFF600000, BAT_BL_1M, BAT_Vs);
/* Map LED registers at 0xFF600300 */
```

## Boot Process Stages

### Stage 1: IPL ROM and IPLCB Creation

The IPL ROM:
1. Performs hardware diagnostics (POST)
2. Creates IPL Control Block (IPLCB)
3. Enumerates MCA/PCI devices
4. Populates BUC (Boot Unit Control) structures
5. Searches for boot device
6. Loads bootloader

### Stage 2: Assembly Entry Point

**Source:** `/sys/arch/rs6000/rs6000/locore.S:__start`

```assembly
__start:
    /* Disable FPU/MMU/exceptions */
    li      0, 0
    mtmsr   0
    isync

    /* Compute end of kernel memory */
#if NKSYMS || defined(DDB) || defined(MODULAR)
    lis     7, _C_LABEL(startsym)@ha
    addi    7, 7, _C_LABEL(startsym)@l
    stw     3, 0(7)
    lis     7, _C_LABEL(endsym)@ha
    addi    7, 7, _C_LABEL(endsym)@l
    stw     4, 0(7)
#else
    lis     4, _C_LABEL(end)@ha
    addi    4, 4, _C_LABEL(end)@l
#endif

    /* Initialize CPU info */
    INIT_CPUINFO(4, 1, 9, 0)

    /* Call C initialization */
    lis     3, __start@ha
    addi    3, 3, __start@l
    bl      _C_LABEL(initppc)
    bl      _C_LABEL(main)
```

### Stage 3: IPLCB Processing

The initppc() function processes the IPLCB:

```c
void initppc(u_long startkernel, u_long endkernel, u_int args, void *btinfo)
{
    /* Indicate boot progress via LED */
    *(uint8_t *)0xe0000030 = '1';

    /* Copy bootinfo */
    memcpy(bootinfo, btinfo, sizeof(bootinfo));
    *(uint8_t *)0xe0000030 = '2';

    /* Get IPLCB information */
    iplcbinfo = lookup_bootinfo(BTINFO_IPLCB);
    if (!iplcbinfo)
        panic("no iplcb information found in bootinfo");

    /* Copy IPLCB to high memory */
    ekern = round_page(endkernel);
    r_iplcb = (struct ipl_cb *)iplcbinfo->addr;
    r_ipldir = (struct ipl_directory *)&r_iplcb->dir;
    memcpy((void *)ekern, r_iplcb, r_ipldir->cb_bitmap_size);

    /* Setup pointers to IPLCB sections */
    iplcb = (struct ipl_cb *)ekern;
    ipldir = (struct ipl_directory *)&iplcb->dir;
    iplinfo = (struct ipl_info *)((char *)iplcb + ipldir->iplinfo_off);
    sysinfo = (struct sys_info *)((char *)iplcb + ipldir->sysinfo_offset);

    /* Extract BUC information */
    for (i = 0; i < sysinfo->num_of_bucs; i++) {
        bucinfo[i] = (struct buc_info *)
            ((char *)iplcb + ipldir->buc_info_off +
             i * sizeof(struct buc_info));
    }
```

### Stage 4: LED Diagnostic Codes

Throughout boot, LED codes indicate progress:

```c
void setled(uint32_t val)
{
    if (led_avail)
        *(uint32_t *)0xFF600300 = val;
}

/* Boot progress indicators */
setled(0x40000000);   /* Have control */
setled(0x40100000);   /* IPLCB copydown successful */
setled(0x40200000);   /* Memory configured */
setled(0x40300000);   /* BATs initialized */
```

The LED register is a 32-bit value where each byte controls 8 LEDs, providing visual feedback during boot.

### Stage 5: Bus and Interrupt Initialization

```c
void cpu_startup(void)
{
    /* Initialize bus space */
    rs6000_bus_space_init();

    /* Setup interrupt controller (IOCC) */
    pic_init();
    pic_iocc = setup_iocc();
    oea_install_extint(pic_ext_intr);

    /* Enable interrupts */
    splraise(-1);
    __asm volatile ("mfmsr %0; ori %0,%0,%1; mtmsr %0"
                  : "=r"(msr) : "K"(PSL_EE));
}
```

## MMU Requirements

### Initial State

- **MMU:** Disabled during locore.S
- **Caches:** Configured based on CPU type
- **Real Mode:** Early boot in real mode

### Supported Processors

- POWER (RSC)
- POWER2
- PowerPC 601
- PowerPC 603/604
- Later PowerPC variants

### Segment Register Setup

RS/6000 uses segment registers for I/O mapping:

```c
extern register_t iosrtable[16];

/* Segment register table for I/O regions */
/* Set up during initialization for device access */
```

### Page Translation

After BAT initialization:
- Main memory uses page tables
- I/O regions use BAT mappings
- Segment registers provide additional mappings
- Hash page table for virtual memory

## Memory Map

### Physical Memory Layout

```
0x00000000 - 0x00003fff    Exception vectors
0x00004000 - RAM_END       Main memory (varies by model)
0x80000000 - 0x8fffffff    MCA/PCI memory space (256MB)
0xC0000000 - 0xcfffffff    MCA/PCI I/O space (256MB)
0xF0000000 - 0xffffffff    I/O regions (256MB)
  0xFF600300                 LED register
  0xFFE00000                 NVRAM
```

### IPLCB Structure Layout

The IPLCB contains:

```c
struct ipl_cb {
    struct ipl_directory dir;      /* Directory of sections */
    /* Followed by variable-length sections: */
    /* - IPL info */
    /* - System info */
    /* - BUC info */
    /* - Vital Product Data */
};

struct ipl_info {
    uint32_t model;                /* Model number */
    uint32_t keyboard_id;
    /* ... */
};

struct sys_info {
    uint32_t num_of_bucs;          /* Number of BUC structures */
    /* ... */
};
```

### BUC (Boot Unit Control)

Each bootable device has a BUC structure describing:
- Device type (SCSI, Ethernet, etc.)
- Device address
- Boot parameters
- Device-specific data

## Build and Installation

### Building the Bootloader

```bash
cd /sys/arch/rs6000/stand
make cleandir
make depend
make

# For cross-compilation:
for i in common boot; do (cd $i; ppc-make); done
cd ../../powerpc/stand/mkbootimage
make
```

### Creating Boot Media

#### Network Boot Image

```bash
# Create network boot image
mkbootimage boot/boot /tmp/boot.fs

# With embedded kernel
mkbootimage -m rs6000 -b boot/boot \
    -k ../compile/YOUR_KERNEL/netbsd /tmp/boot.fs
```

#### Network Boot Setup

1. Configure BOOTP/DHCP server
2. Configure TFTP server with boot image
3. Set up IPL ROM to boot from network

```bash
# On boot server:
# /etc/bootptab entry
rs6000:\
    :ht=ethernet:\
    :ha=001122334455:\
    :ip=192.168.1.100:\
    :sm=255.255.255.0:\
    :bf=/tftpboot/rs6000/boot.fs:

# TFTP directory
mkdir -p /tftpboot/rs6000
cp /tmp/boot.fs /tftpboot/rs6000/
cp netbsd /tftpboot/rs6000/
```

#### Hard Disk Installation

```bash
# Install bootloader to disk
# (Specific procedure varies by RS/6000 model)
dd if=boot.fs of=/dev/rsd0a bs=512
```

## Debugging

### LED Diagnostic Codes

The RS/6000's front panel LEDs are the primary debugging interface:

```c
/* LED code meanings during boot */
0x00000000   /* Initial state */
0x40000000   /* Bootloader has control */
0x40100000   /* IPLCB copied successfully */
0x40200000   /* Memory configured */
0x40300000   /* BAT initialization */
0x40400000   /* Entering kernel */
0x55500000   /* Debug breakpoint (debug builds) */
0xFFFFFFFF   /* Error condition */
```

### Reading LED Codes

The LED register at 0xFF600300 displays 32 bits (4 bytes of 8 LEDs each). Each bit corresponds to one LED on the front panel.

### Serial Console

Configure serial console:

```c
#define CONCOMADDR 0x30        /* Serial port address offset */
#define CONSPEED 9600          /* Default baud rate */
```

Serial port parameters:
- Port: Integrated serial port
- Speed: 9600 baud (configurable)
- Format: 8N1

### IPLCB Inspection

Add debug output to examine IPLCB:

```c
void dump_iplcb(void)
{
    printf("IPL CB Information:\n");
    printf("  Model: 0x%x\n", iplinfo->model);
    printf("  Num BUCs: %d\n", sysinfo->num_of_bucs);
    printf("  CB size: %d\n", ipldir->cb_bitmap_size);

    for (i = 0; i < sysinfo->num_of_bucs; i++) {
        printf("  BUC %d: type=0x%x\n", i, bucinfo[i]->device_type);
    }
}
```

### DDB Kernel Debugger

Enable debugging in kernel:
```c
options DDB
options DDB_HISTORY_SIZE=512
```

Break into debugger:
- Via panic
- Serial break signal
- Programmatic Debugger() call

### Common Boot Issues

**Problem:** LED shows 0x00000000, no boot
- **Cause:** Boot device not found
- **Solution:** Check cabling, verify boot device

**Problem:** LED stops at early code
- **Cause:** Hardware failure or bad bootinfo
- **Solution:** Check hardware, update IPL ROM

**Problem:** "no iplcb information"
- **Cause:** Bootloader/kernel mismatch
- **Solution:** Rebuild both together

**Problem:** Network boot fails
- **Cause:** BOOTP/TFTP misconfiguration
- **Solution:** Verify network setup, check server logs

### Low-Level Debugging

Insert LED updates for debugging:


## Platform-Specific Notes

### Model Numbers

RS/6000 model numbering:
- 7006: Tower workstations
- 7012: Desktop workstations
- 7013: Rack-mount servers
- 7015: Tower servers
- 7016: Desktop workstations

### MCA vs PCI

Different RS/6000 models use different buses:
- **MCA (Micro Channel Architecture):** Older models
- **PCI:** Newer models (mid-1990s onward)
- Some models have both MCA and PCI

The bus type is detected from IPLCB/BUC information.

### IOCC Interrupt Controller

RS/6000 systems use the IOCC (I/O Channel Controller):
- Custom IBM interrupt controller
- Handles MCA bus interrupts
- Different from standard PIC or OpenPIC
- Configured via IPLCB data

### Processor Types

The port supports:
- POWER (RSC) - Original RISC Single Chip
- POWER2 - Enhanced POWER architecture
- PowerPC 601 and later

Processor type detected at runtime.

### Graphics

Many RS/6000 systems have:
- No graphics (serial console only)
- IBM GXT graphics adapters
- Third-party graphics cards

NetBSD typically uses serial console on RS/6000.
