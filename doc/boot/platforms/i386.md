# NetBSD/i386 Boot Documentation

$NetBSD$

## Platform Overview

**Architecture**: Intel/AMD x86 32-bit
**Port Date**: 1993-03-21
**Boot Method**: Multi-stage (MBR → bootxx → boot → kernel)
**Firmware**: BIOS, UEFI (32-bit)
**MMU Requirements**: Real mode → Protected mode transition

## Hardware Support

- **CPU**: Intel 80386 and later, AMD x86 processors
- **Memory**: Up to 4GB physical address space (PAE can extend to 64GB)
- **Boot Devices**: Hard disk, floppy, CD/DVD, USB, network (PXE)
- **Firmware**: IBM PC BIOS, UEFI 32-bit

## Boot Process

### Stage 0: BIOS/Firmware

1. **Power-On Self Test (POST)**
2. **Boot device selection** (configured in BIOS setup)
3. **Load first sector** (512 bytes) to physical address 0x7C00
4. **Transfer control** to loaded boot sector

### Stage 1: Master Boot Record (MBR)

**Location**: `/sys/arch/i386/stand/mbr/`
**Size**: Exactly 512 bytes
**Load Address**: 0x7C00

**MBR Variants**:
- `mbr` - Standard MBR with partition selection
- `gptmbr` - GPT-aware MBR for GUID Partition Tables
- `mbr_bootsel` - Interactive boot menu with partition selection
- `mbr_com0` - Serial console MBR (115200 baud)
- `mbr_ext` - Extended partition support

**Functionality**:
- Read partition table
- Select active partition (or user-selected partition)
- Load Partition Boot Record (PBR) to 0x8800
- Transfer control to PBR

### Stage 2: Primary Bootloader (bootxx)

**Location**: `/sys/arch/i386/stand/bootxx/`
**Size**: Maximum 15 sectors (7680 bytes)
**Load Address**: 0x1000

**Filesystem-Specific Variants**:
- `bootxx_ffsv1` - Fast File System v1
- `bootxx_ffsv2` - Fast File System v2 (64-bit block numbers)
- `bootxx_ext2fs` - Linux ext2/ext3 filesystem
- `bootxx_lfsv1` - Log-structured Filesystem v1
- `bootxx_lfsv2` - Log-structured Filesystem v2
- `bootxx_msdos` - FAT12/FAT16 filesystem
- `bootxx_ustarfs` - USTAR tape archive format

**Functionality**:
- Minimal filesystem reading support
- Locate `/boot` file on boot partition
- Load `/boot` to memory address 0x10000
- Transfer control to secondary bootloader

### Stage 3: Secondary Bootloader (boot)

**Location**: `/sys/arch/i386/stand/boot/`
**Load Address**: 0x10000 (64KB)
**Heap**: 0x40000 - 0x70000 (192KB)

**Features**:
- Full filesystem support (FFS, ext2fs, LFS, FAT, CD9660)
- Disk I/O via BIOS INT 13h (CHS and LBA modes)
- Network boot support (TFTP, NFS via PXE)
- Interactive command line interface
- Kernel loading (ELF, gzip-compressed)
- Boot parameter passing
- Serial and VGA console support
- Multi-boot protocol support (version 1 and 2)

**Supported Commands**:
```
boot [kernel] [-flags]  - Boot specified kernel
ls [path]               - List files
consdev {pc|com0|com1}  - Select console device
dev [device]            - Set default boot device
help                    - Display command help
quit                    - Exit bootloader
```

**Boot Variants**:
- `biosboot` - Standard BIOS boot
- `pxeboot` - Network boot via PXE
- `cdboot` - CD/DVD boot (El Torito)
- `dosboot` - DOS COM executable bootloader
- `efiboot` - UEFI 32-bit boot

### Stage 4: Kernel

**Load Address**: Virtual address 0xC0100000
**Entry Point**: Kernel `start` symbol

**Handoff**:
- Boot loader passes parameters via memory structures
- Memory map from BIOS (INT 15h, E820)
- Boot device information
- Kernel symbol table (optional)
- Framebuffer information (for graphical console)

## MMU Setup

### Real Mode (Initial State)

**Characteristics**:
- 16-bit instruction mode
- 20-bit addressing (1MB limit)
- Segmented memory model
- BIOS INT services available

**Memory Layout**:
```
0x00000000 - 0x000003FF : Interrupt Vector Table (IVT)
0x00000400 - 0x000004FF : BIOS Data Area (BDA)
0x00000500 - 0x00007BFF : Free conventional memory
0x00007C00 - 0x00007DFF : Boot sector load area (MBR)
0x00008800 - 0x00008FFF : PBR load area
0x00001000 - 0x00001FFF : bootxx load area
0x00010000 - 0x0003FFFF : boot (secondary bootloader)
0x00040000 - 0x00070000 : boot heap
0x00080000 - 0x0009FFFF : Extended BIOS Data Area (EBDA)
0x000A0000 - 0x000BFFFF : VGA video memory
0x000C0000 - 0x000FFFFF : ROM BIOS
0x00100000+             : Extended memory (accessible via unreal mode)
```

### Protected Mode Transition

**Location**: `/sys/arch/i386/stand/lib/realprot.S`

#### Global Descriptor Table (GDT)

The bootloader sets up a 7-entry GDT:

```c
struct segment_descriptor {
    unsigned sd_lolimit:16;  /* segment limit 0..15 */
    unsigned sd_lobase:24;   /* segment base 0..23 */
    unsigned sd_type:5;      /* segment type */
    unsigned sd_dpl:2;       /* descriptor privilege level */
    unsigned sd_p:1;         /* segment present */
    unsigned sd_hilimit:4;   /* segment limit 16..19 */
    unsigned sd_avl:1;       /* available for system use */
    unsigned sd_long:1;      /* long mode (64-bit) */
    unsigned sd_def32:1;     /* default 32-bit operands */
    unsigned sd_gran:1;      /* granularity (4KB vs byte) */
    unsigned sd_hibase:8;    /* segment base 24..31 */
};
```

**GDT Entries**:
1. **NULL descriptor** (required by CPU)
2. **Flat code segment**: Base 0x00000000, Limit 0xFFFFFFFF, 4KB granularity, 32-bit
3. **Flat data segment**: Base 0x00000000, Limit 0xFFFFFFFF, 4KB granularity, 32-bit
4. **Boot code segment**: Patched at runtime for current CS base
5. **Boot data segment**: Patched at runtime for current DS base
6. **Boot real mode segment**: 1-byte granularity, 16-bit (for BIOS calls)
7. **Boot real data segment**: 1-byte granularity, 16-bit

#### Transition Sequence

**Function**: `real_to_prot()`

```assembly
; 1. Disable interrupts
cli

; 2. Enable A20 gate (access memory above 1MB)
call enable_a20

; 3. Load GDT register
lgdt [gdtdesc]

; 4. Set PE bit in CR0 (enable protected mode)
mov eax, cr0
or eax, 0x01        ; CR0_PE
mov cr0, eax

; 5. Far jump to reload CS with protected mode selector
jmp 0x08:protmode   ; 0x08 = flat code segment selector

protmode:
; 6. Load data segment registers
mov ax, 0x10        ; 0x10 = flat data segment selector
mov ds, ax
mov es, ax
mov fs, ax
mov gs, ax
mov ss, ax

; 7. Set up protected mode stack
; (already configured)
```

**Special Handling - VIA C3 EPIA**:
- VIA C3 processors have branch prediction cache issues
- Workaround: Flush prefetch queue 16 times after mode switch
- Implemented as `EPIA_HACK` in realprot.S

#### Return to Real Mode

**Function**: `prot_to_real()`

Required for BIOS interrupt calls from protected mode:

```assembly
; 1. Load 16-bit segment descriptors
mov ax, 0x30        ; Boot real mode segment
mov ds, ax
mov es, ax
mov fs, ax
mov gs, ax

; 2. Far jump to 16-bit code segment
jmp 0x28:realmode

realmode:
; 3. Clear PE bit in CR0
mov eax, cr0
and eax, ~0x01
mov cr0, eax

; 4. Far jump to reload CS with real mode segment
jmp segment:offset

; 5. Reload segment registers for real mode
mov ax, segment
mov ds, ax
mov es, ax
mov ss, ax

; 6. Enable interrupts
sti
```

### A20 Gate Handling

**Purpose**: Enable access to memory above 1MB

**Methods** (tried in order):
1. **BIOS INT 15h, AX=2401h** - Modern BIOS enable
2. **Keyboard controller** (port 0x64/0x60) - Traditional method
3. **Fast A20** (port 0x92) - Chipset-specific
4. **Already enabled** - Check and skip if active

### Memory Detection

**BIOS INT 15h Functions**:

1. **E820** (preferred, modern):
   ```
   Function: INT 15h, AX=E820h
   Returns: Memory map with type information
   Types: Available RAM, Reserved, ACPI, NVS
   ```

2. **E801** (older):
   ```
   Function: INT 15h, AX=E801h
   Returns: Memory in 1KB and 64KB blocks
   ```

3. **88** (oldest):
   ```
   Function: INT 15h, AH=88h
   Returns: Extended memory in KB
   ```

## Disk I/O

### BIOS INT 13h Interface

**CHS (Cylinder-Head-Sector) Mode**:
- **INT 13h, AH=02h**: Read sectors
- **Limitations**: 1024 cylinders, 256 heads, 63 sectors
- **Maximum**: 8GB disk size

**LBA (Logical Block Addressing) Mode**:
- **INT 13h, AH=42h**: Extended read
- **Disk Address Packet (DAP)**:
  ```c
  struct disk_address_packet {
      uint8_t  size;       /* Packet size (16 or 24) */
      uint8_t  reserved;   /* Must be 0 */
      uint16_t count;      /* Number of blocks */
      uint32_t buffer;     /* Transfer buffer address */
      uint64_t lba;        /* Starting LBA */
  };
  ```
- **Maximum**: 2^64 sectors (9.4 ZB with 512-byte sectors)

### Device Naming

**Bootloader notation**:
- `hd0` - First hard disk (BIOS 0x80)
- `hd1` - Second hard disk (BIOS 0x81)
- `hd0a` - First partition, BSD label 'a'
- `fd0` - First floppy disk (BIOS 0x00)
- `cd0` - CD/DVD drive

**Kernel notation**:
- `wd0` - First IDE/SATA disk
- `sd0` - First SCSI disk
- `wd0a` - Root partition

## Network Boot (PXE)

**Location**: `/sys/arch/i386/stand/pxeboot/`

**PXE Boot Flow**:

1. **DHCP request** - Obtain IP address and boot server
2. **TFTP download** - Load `pxeboot_ia32.bin` from boot server
3. **Load kernel** - Fetch kernel via TFTP or mount root via NFS
4. **Network root** - Boot with NFS-mounted root filesystem

**PXE Memory Layout**:
- Load address: 0x10000
- Heap: 0x20000 - 0x40000 (128KB, smaller than biosboot)
- PXE API buffers: Protected memory regions

**Environment Variables**:
- `boot.nfs.server` - NFS server IP
- `boot.nfs.path` - Root filesystem path

## UEFI Boot (32-bit)

**Location**: `/sys/arch/i386/stand/efiboot/`

**EFI Boot Flow**:

1. **EFI firmware** - Load `bootia32.efi` from EFI System Partition (ESP)
2. **EFI Boot Services** - Access to disk, network, graphics
3. **Load kernel** - Read from FAT32 ESP or other filesystems
4. **Exit Boot Services** - Transfer control to kernel

**EFI Features**:
- Native filesystem access (no BIOS INT 13h)
- Modern graphics (GOP - Graphics Output Protocol)
- ACPI table access
- Larger memory space (still 32-bit addressing)

## Installation

### installboot(8)

**Install bootloader**:
```sh
# Install FFS bootloader
installboot /dev/rwd0a /usr/mdec/bootxx_ffsv1

# Install MBR
fdisk -i wd0
installboot -o timeout=5 /dev/rwd0a /usr/mdec/bootxx_ffsv1
```

**For GPT disks**:
```sh
gpt biosboot -i 1 wd0
installboot -o timeout=5 /dev/rwd0a /usr/mdec/bootxx_ffsv1
```

### File Locations

**Installed bootloaders**: `/usr/mdec/`
- `mbr` - Master Boot Record
- `bootxx_ffsv1`, `bootxx_ffsv2` - Primary bootloaders
- `boot` - Secondary bootloader (copied to `/boot` on filesystem)

## Debugging

### Serial Console

**Enable at boot time**:
```
consdev com0
boot -h
```

**Permanent setting**:
```sh
echo "consdev com0" > /boot.cfg
```

**Serial parameters**: 115200 baud, 8N1 (8 data bits, no parity, 1 stop bit)
**Port**: COM1 (0x3F8), COM2 (0x2F8)

### Boot Configuration File

**Location**: `/boot.cfg`

```
banner=Welcome to NetBSD
banner================
menu=Boot normally:boot netbsd
menu=Boot single user:boot netbsd -s
menu=Boot with ACPI disabled:boot netbsd -2
menu=Drop to boot prompt:prompt
timeout=10
default=1
clear=1
```

### Verbose Boot

**Bootloader verbose mode**:
```
boot -v netbsd
```

**Kernel verbose boot**:
```
boot netbsd -v
```

## Troubleshooting

### Common Issues

**Bootloader doesn't start**:
- Check active partition flag in partition table
- Verify MBR is installed correctly
- Use `fdisk -u` to update MBR

**"Missing operating system"**:
- MBR cannot find active partition
- Partition boot record is missing or corrupted
- Reinstall bootxx: `installboot /dev/rwd0a /usr/mdec/bootxx_ffsv1`

**"Error loading /boot"**:
- bootxx cannot locate `/boot` file
- Filesystem corruption
- Wrong bootxx variant for filesystem type

**Hangs at "Boot from ..."**:
- A20 gate not enabled (very old hardware)
- Memory detection failure
- Try different BIOS settings

**Boot with wrong console**:
- Set `consdev` in boot.cfg
- Use serial console bootloader variant: `mbr_com0`

## Platform-Specific Considerations

### CPU Requirements

- **Minimum**: Intel 80386DX or compatible
- **Recommended**: Intel Pentium or later
- **Features used**:
  - Protected mode (386+)
  - Page size extensions (optional, 486+)
  - PAE (optional, Pentium Pro+)
  - ACPI (optional, Pentium II+)

### Memory Constraints

- **Bootloader requires**: 640KB conventional memory minimum
- **Kernel requires**: 8MB RAM minimum, 32MB+ recommended
- **Large kernels**: May require extended memory access

### Legacy Hardware

**PS/2 MCA (Micro Channel Architecture)**:
- Special MBR variant available
- ABIOS interface support

**VIA C3 Processors**:
- EPIA_HACK enabled by default in realprot.S
- Flushes prefetch queue after mode transitions
